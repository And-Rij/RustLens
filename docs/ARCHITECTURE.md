# Архітектура першої версії

Реалізовано захоплення, виділення, OCR, локальний переклад і редагування тексту (BLOCK_1.md, BLOCK_2.md). SQLite-історія й файловий експорт Anki також реалізовані (BLOCK_3.md). AnkiConnect — майбутня інтеграція.

## Розподіл відповідальності

| Частина | Рішення | Призначення |
| --- | --- | --- |
| Desktop | Tauri 2 | Вікна, команди Rust, події, глобальна гаряча клавіша |
| Інтерфейс | React + TypeScript + shadcn/ui | Вибір області, переклад, історія, налаштування |
| Захоплення | Windows-адаптер у Rust | Отримати кадр до показу вікна виділення |
| OCR | `ocrs` + RTen | Локально розпізнати англійський текст |
| Переклад | `reqwest` → Ollama `/api/chat` | Використати встановлену локальну модель |
| Дані | SQLite через `rusqlite` | Історія й позначки для експорту |
| Anki | UTF-8 `.txt`, поля через табуляцію | Імпорт без додаткового Anki add-on |

HTTP, база даних, OCR і файловий експорт виконуються у Rust. React отримує типізовані результати через Tauri-команди. Важкі операції не блокують інтерфейс; синхронні OCR/SQLite виклики виконуються у блокувальному worker, запити Ollama — асинхронно.

## Основний сценарій

1. Зареєстрована гаряча клавіша спрацьовує навіть коли головне вікно сховане.
2. Rust захоплює поточний кадр потрібного монітора, перш ніж показати вікно виділення. Завдяки цьому до OCR не потрапляє власний інтерфейс.
3. Вікно показує захоплений кадр; користувач виділяє прямокутник. Це фіксує зображення, але не зупиняє саму гру.
4. Координати перетворюються з логічних у фізичні з урахуванням DPI та позиції монітора. Rust обрізає кадр і запускає OCR.
5. Віконце результату показує англійський текст і стан перекладу. Текст можна виправити й перекласти повторно.
6. Ollama повертає переклад. Успішний запис зберігається в історії.
7. Користувач позначає корисну фразу для навчання; у головному вікні експортує вибрані записи.

Запит має ідентифікатор, щоб старий результат не замінив новий. На старті допускається один активний переклад; повторне натискання не запускає паралельно ще одну модель. Escape закриває виділення/результат. Віконце обмежується робочою областю монітора.

## Повноекранні ігри

Захоплення кадру та показ вікна поверх гри — дві окремі перевірки. `always_on_top` не слід вважати доказом підтримки exclusive fullscreen. Початкове захоплення реалізовано через XCap. Інший адаптер вибиратимемо за результатами тесту в Limbus Company.

Потрібно перевірити windowed, borderless fullscreen та exclusive fullscreen на конкретних іграх, включно з втратою фокусу. Якщо exclusive fullscreen не працює, задокументувати результат і варіант borderless; вимога залишається відкритою. HDR, другий монітор і масштабування потребують окремих перевірок. Універсальна сумісність з anti-cheat не заявляється.

Основна тестова гра — Limbus Company. Доступні режими та результати фіксуємо в [GAME_TESTS.md](GAME_TESTS.md). Назву «Fullscreen» у налаштуваннях гри не вважаємо підтвердженням exclusive fullscreen.

## OCR

`ocrs` — бібліотека Rust, яка наразі розпізнає латиницю й потребує моделей detection/recognition. Автор позначає її як early preview; дві OCR-моделі підключені, тестове зображення розпізнається правильно. Якість і швидкість на ігрових скриншотах ще треба перевірити. Для повної офлайн-роботи OCR-моделі спочатку мають бути доступні локально.

Windows OCR не обрано основою: Microsoft офіційно підтримує `Windows.Media.Ocr` для desktop-програм з package identity (MSIX), що додає вимоги до пакування. Якщо `ocrs` не пройде тест, окремо порівняти альтернативи, включно з Tesseract. Не міняти рушій до отримання конкретних результатів.

## Модель

Початкова модель — вже наявна `translategemma:12b`. Формат запиту — офіційний шаблон TranslateGemma, напрям English (`en`) → Ukrainian (`uk`), тільки переклад у відповіді. Текст гри передається як матеріал для перекладу.

`gemma4:12b` залишаємо для майбутніх пояснень/прикладів або порівняльного тесту якості. Не тримаємо дві великі моделі одночасно лише заради перекладу. Контекст для коротких фрагментів обмежуємо; значення визначаємо вимірюванням. Завантаження, час перекладу, FPS гри та VRAM вимірюємо разом. Розмір файлу моделі не дорівнює споживанню VRAM.

Обробка помилок: Ollama недоступна, модель відсутня, таймаут, порожня відповідь, OCR без тексту, захоплення недоступне, збій збереження. Розпізнаний текст не губиться після помилки перекладу. Збій збереження показується окремо від успіху перекладу.

## Історія й Anki

Мінімальний запис: `id`, `source_text`, `translation`, `source_language`, `target_language`, `model`, `created_at`, `selected_for_study`. Метадані гри/вікна можна додати, коли реалізоване їх отримання. Тексти успішних перекладів зберігаються у SQLite в app_data_dir. Зображення залишаються лише в пам'яті. Ключ фрази нормалізує пробіли й переноси; повторний переклад оновлює запис зі збереженням позначки.

Історія читається сторінками з бази, підтримує пошук. Окремі поняття: автоматична історія перекладів і свідомо вибраний навчальний матеріал. У першій версії карткою може бути ціле речення; редактор окремих слів/фраз — наступний етап.

Експорт: Front — англійський текст, Back — переклад, Tags — `rustlens`. UTF-8, tab-separated `.txt`, з правильним екрануванням табуляцій, лапок і переносів. Інструкція імпорту описує тип нотатки Basic, відповідність полів і вибір колоди. Успішний експорт підтверджується реальним імпортом в Anki; повторні експорти перевіряються на дублікати.

AnkiConnect уже доступний локально (API 6). Це дозволяє пізніше додати пряме збереження через Rust HTTP-клієнт. Вибір колоди й типу нотатки, перевірка відповідності полів та захист від повторного додавання мають бути частиною цього блоку. Збереження картки викликається явно користувачем; запис історії не повинен автоматично створювати картку. AnkiConnect не є передумовою файлового експорту.

## Інтерфейс

Три прості вкладки: «Переклад», «Історія», «Налаштування». Окремо — тимчасове вікно виділення й маленьке вікно результату. Стандартні компоненти shadcn/ui, українські підписи, без окремої складної дизайн-системи. Перед написанням UI зафіксувати короткий опис поведінки й доступності.

## Майбутній Linux

Захоплення/глобальні клавіші ізольовані в платформних модулях; переклад, історія й експортери залишаються спільними. Підтримка Linux ще не реалізована. X11 та Wayland потребують окремого дослідження дозволів і механізмів захоплення.
